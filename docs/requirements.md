# Требования к первой версии (MVP)

Подготовлено 2026-11-21: аналитик по описанию поведения прежней реализации, затем решения владельца. Код прежней реализации не использовался.

## Решения владельца (2026-11-21)

| Вопрос | Решение |
|---|---|
| Двоение текста при первом рендере модуля с активной темой | **Входит в MVP.** Сначала исследование причины, затем фикс в рамках SKIP-ONLY |
| Источники данных | **Всё заново.** Палитру, хеши значков и раскладку глифов снимаем сами на живом конфигураторе своим инструментом. Архитектор и разработчик не читают исходники прежней реализации |
| Инструменты загрузки | **Нативный загрузчик (.exe)** на C++, без Python. Watcher — после MVP |
| Значок «Сохранить» | **В MVP**, сразу таблицей хеш → PNG; рисунок делается заново |
| Палитра | **Во внешнем JSON** с первой версии; читается один раз при старте, ошибка чтения не роняет процесс |
| Перерисовка | **Без ресайза** — исследование входит в MVP; ручной ресайз остаётся запасным путём |
| Диалоги и формы объектов | **В MVP**: снять палитру этих окон и дополнить карту |
| Ручная настройка цветов в параметрах конфигуратора | **Не должна требоваться.** В прошлой версии цвета шрифтов и фонов приходилось настраивать вручную; в новой тема работает без ручных правок настроек. Способ (перекраска при отрисовке или автоматическая правка настроек с откатом) выбирает архитектор, правка настроек 1С — отдельное решение владельца |
| Замеры и визуальная приёмка | Оркестратор может снимать цвета и проверять вид через снимки экрана (computer use); снимки с кодом конфигурации в git не попадают |
| Палитра дизайнера M3a (2026-11-22) | **Принята** (`themes/default/palette.json`) с осветлением операторов, комментариев и препроцессора в схеме редактора до контраста ≥ 4,5 к фону (см. ниже) |

Допущения: платформа 1С 8.3.14–8.5.1, Windows 10/11 x64; основной стенд — x64-конфигуратор 8.3.27; 32-битного конфигуратора сейчас нет, живой x86-цикл — долг, не блокер; приёмку глазами делает владелец; логи и снимки экрана с кодом конфигурации в git не попадают.

## Целевая схема редактора модулей (от владельца, 2026-11-21)

Владелец задавал эти значения вручную в «Сервис → Параметры → Модули → Редактирование»; фон при этом оставлял белым, его затемняла тема. В новой версии редактор должен выглядеть так **без ручной настройки**.

| Элемент | Цвет |
|---|---|
| Ключевые слова | `#DC8500` |
| Константы «Число», «Строка», «Дата» | `#F8F8E8` |
| Идентификаторы | `#F8F8E8` |
| Операторы | `#F05454` (решение владельца 2026-11-22: контраст к фону `#202028` ≥ 4,5, 4,70; было `#C82626`) |
| Комментарии | `#4B90C7` (решение владельца 2026-11-22: контраст к фону `#202028` ≥ 4,5, 4,71; было `#4585B8`) |
| Препроцессор | `#E86020` (решение владельца 2026-11-22: контраст к фону `#202028` ≥ 4,5, 4,72; было `#BA3E00`) |
| Текущий идентификатор | `#8465C5` |
| Выбранный идентификатор | `#B4B4B4` |
| Границы блока | `#4133A3` |
| Прочее | `#F8F8E8` |
| Фон | `#202028` |
| Фон результатов поиска | `#A01E64` |
| Фон контекстной подсказки | `#525278` |
| Шрифт | Fira Code Retina, 11 |

Вопросы к архитектуре:
- Перекраска при отрисовке различает категории только по исходному цвету. Если у 1С по умолчанию две категории с разными целевыми цветами рисуются одним цветом (например, ключевые слова и операторы), их не развести. Цвета 1С по умолчанию для каждой категории нужно снять замером.
- Шрифт перекраской не заменить: нужна либо подмена шрифта при создании (новая точка перехвата — решение владельца), либо правка настроек.
- Если пользователь уже настроил цвета сам, тема должна давать ту же схему, а не перекрашивать его цвета второй раз.

## 1. Что видит пользователь

- Тема применяется к **уже открытому** конфигуратору (`1cv8.exe` с видимым окном «Конфигуратор»), файлы платформы не меняются.
- Тёмные: редактор модулей (с подсветкой лексем), дерево конфигурации и палитра свойств (отличимы от редактора), меню и контекстные меню (без двойного текста и белого бокса выделения), справка F1 и синтакс-помощник (тёмные с первого кадра, без жёлтой шапки, ссылки читаемы), панели команд и рамки, диалоги и формы объектов.
- Значок «Сохранить» на панели команд — тёмный вариант; остальные значки пока оригинальные.
- Две сборки — x86 (WOW64) и x64 — из одного исходника; DLL чужой битности не загружается.
- Загрузка вручную нативным загрузчиком; успех — модуль виден в процессе; повторная загрузка отклоняется.
- Выгрузка снимает только свой модуль, процесс жив, интерфейс снова светлый без запечённых артефактов.
- Для цветов вне карты — правило: бледные тона считаются фонами и темнеют, насыщенные сохраняют оттенок. Алгоритм выбирают архитектор и дизайнер.

## 2. Инварианты (не обсуждаются)

- **SKIP-ONLY:** не дорисовывать в контекст отрисовки и не писать пиксели чужих surface. Допустимо менять цвет до отрисовки или пропускать дубль.
- **Поздняя загрузка:** только после видимого окна «Конфигуратор» и паузы ≥ 25 с. Хуки не должны работать, пока 1С строит стартовые кэши.
- Без IFEO, автозагрузки (`HKCU\...\Run`) и копирования в `System32`/`SysWOW64`.
- Цель — только образ `1cv8.exe` с окном «Конфигуратор»; не толстый клиент, не `1cv8c.exe`, не произвольный pid. Несовпадение — отказ без открытия процесса на запись.
- Хуки темы — только `cairo.dll`, `gdi32.dll`, `user32.dll`. Новый модуль — отдельное решение владельца.
- Выгрузка полностью возвращает исходные вызовы, включая адреса, которые модули получили до выгрузки.
- Поздно загружаемые модули (F1, диалоги) красятся с первого кадра. Многопоточность cairo учитывается.
- В хуке нет сети, шелла, чтения конфигурации 1С. Текст модулей и интерфейса в лог не пишется. Файлы (палитра, значки) читаются один раз при старте, не в горячем пути.
- Пропуск глифов включается только при подтверждённой раскладке структуры глифа для этой платформы и битности.

## 3. Дефекты, которые нужно закрыть или не ухудшить

- Не ухудшить: двоение справки (emboss-пара), двойной текст меню, белые боксы выделения, жёлтая шапка F1, нечитаемые ссылки, невидимый текст.
- Закрыть: задержку тёмной темы в поздних окнах; падения и висячие указатели при выгрузке; повторную загрузку.
- **Закрыть в MVP (решение владельца):** двоение текста редактора при первом рендере с активной темой; перерисовку без ресайза окна.
- Позже: остальные значки, GUI профилей, синтетический bold WebKit (врождённый, только не ухудшать), watcher.

## 4. «Эффективнее» — измеримые критерии

Базовые замеры прежней реализации на стенде снимаются до сравнения.

- Накладные расходы горячих хуков: не более +5 % времени кадра при прокрутке большого модуля; без блокировок и выделения памяти на вызов.
- Время применения: ≤ 2 с от загрузки до первой тёмной перерисовки (без обязательной паузы 25 с).
- Время выгрузки: ≤ 2 с, процесс жив.
- Размер DLL — не больше прежней, без внешних CRT-зависимостей (проверка по импортам).
- Стабильность: ≥ 20 циклов загрузка → выгрузка подряд без падений и утечек сверх допуска; процесс живёт с темой ≥ 1 ч.
- Поддерживаемость: одна кодовая база на две битности; логика цвета в одном месте; сборка одной командой на битность; без адресов и сигнатур, привязанных к версии платформы.
- Данные отдельно от кода: добавить цвет — правка только JSON.
- Диагностика: счётчики и причины отказов в логе, без текста интерфейса.

## 5. Критерии приёмки MVP

Цикл: окно «Конфигуратор» открыто ≥ 25 с → загрузка → перерисовка → выгрузка. На x64 — живьём, на x86 — сборка и статическая проверка, пока нет 32-битного конфигуратора.

- Обе DLL и загрузчик собираются одной командой на битность.
- Отказ на чужой цели и при несовпадении битности: ненулевой код, процесс не открывается на запись. Повторная загрузка — отказ.
- После загрузки и перерисовки (без ресайза) все части из п. 1 тёмные по карте.
- Модуль, впервые открытый при активной теме, не двоится.
- Справка F1 и диалоги, открытые после загрузки, тёмные с первого кадра.
- Значок «Сохранить» тёмный под темой, светлый после выгрузки, снова тёмный при повторной загрузке.
- Нет записи пикселей и дорисовки (ревью по SKIP-ONLY; кадр в светлой теме до загрузки и после выгрузки совпадает).
- Выгрузка: модуль исчез, процесс жив ≥ 5 мин, интерфейс светлый; выгрузка чужого модуля отклоняется.
- Метрики п. 4 сняты и в границах.
- Лог: счётчики и отказы есть, текста интерфейса нет.
