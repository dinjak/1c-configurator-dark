# Задание: веха M3b — живой замер probe

Контекст: `docs/architecture.md`, разделы «Загрузчик» (`probe-dump`, код 18) и «Замер». Probe ставит три хука `cairo.dll` только на чтение и всегда вызывает исходную функцию; данные снимаются `probe-dump` в JSON (stdout). Код прежней реализации (`D:\projects\darktheme`) не читать.

## Стенд и правила

- Тестовая ИБ `D:\tmp\Платформа\1`, конфигуратор x64 8.3.27, светлая тема, тема **не** загружена.
  `"C:\Program Files\1cv8\8.3.27.1989\bin\1cv8.exe" DESIGNER /F"D:\tmp\Платформа\1"`
- Каждый `probe-load` — только после подтверждения «окно „Конфигуратор“ открыто ≥ 25 с» (оркестратор спрашивает владельца). Загрузчик сам наблюдает окно ещё 25 с.
- Действия в 1С — основная сессия (computer use) или владелец. Тестировщик и роли кликов не делают.
- Дампы — только в scratchpad сессии: `cfgdark_x64 probe-dump > <scratchpad>\D0.json`. В репозиторий, `logs/` и `docs/` — не класть; в документацию — только числа, hex и basename. Перенаправлять через `cmd /c "… > файл"`: `>` в Windows PowerShell 5.1 дописывает BOM (или читать файл как `utf-8-sig`). Окно конфигуратора должно быть развёрнуто: у свёрнутого окна хуки не получают вызовов.
- Каждый `probe-dump` обнуляет счётчики эпохи (`calls`, `hits`, `runs`, `glyphs`, `alpha_lt1.calls`, `dup`, `frame`). Шкала `timeline`, `first_ms`, `layout` и `overflow` копятся с `DtStart`.
- Сессия не дольше 15 мин (шкала — 4096 корзин по 250 мс ≈ 17 мин).

## Smoke (тестировщик, до сессий)

1. `build.cmd x64` и `build.cmd x86` — 0 failed.
2. `cfgdark_x64 status` — probe «готова», цель одна.
3. После подтверждения владельца: `cfgdark_x64 probe-load` → код 0.
4. `cfgdark_x64 probe-dump` → код 0, JSON разбирается; записать `hooks.*.state`, `hooks.*.patch`, `getters_missing`, `features`, `patch`.
5. Второй `probe-dump` через 5–10 с → `epoch` = 2, `t_prev_ms` = `t_ms` первого.
6. `cfgdark_x64 probe-unload` → код 0; `status` — probe «нет», объект активности «нет».
7. 1С жив, кадр светлый, без артефактов (визуально — основная сессия).

Стоп и вопрос владельцу: `DtStart` вернул 3 (не найден `cairo.dll` или ни одного хука), 4 (ACG) или 5; любой хук `failed`; 1С упал или завис.

## Сессия 1

1. Запуск конфигуратора → подтверждение владельца → сразу `probe-load` (25 с держит загрузчик).
2. Готовность без ввода: D0 сразу после `probe-load`, D1 через 10 с, D2 через 30 с, D3 через 60 с.
3. Пары «дамп → действие → 10–30 с → дамп»:
   - S1 — прокрутка большого модуля (≥ 1000 строк; модуль создаётся один раз в тестовой ИБ) 10 с;
   - S2 — открыть новый модуль;
   - S3 — прокрутить его 10 с;
   - S4 — F1 впервые;
   - S5 — главное и контекстное меню, по 5 раз;
   - S6 — «Параметры», пройти вкладки, «Отмена»;
   - S7 — 10 наведений на «Сохранить» между дампами;
   - S8 — контроль: 10 наведений на соседнюю кнопку;
   - S9 — пробел в модуле → дамп → Ctrl+Z → дамп;
   - S10 — свернуть и развернуть окно дважды.
4. `probe-unload`.

## Сессия 2

S1–S3 с цветами редактора по умолчанию — по процедуре M3a (`docs/measurements.md`): резервная копия `%APPDATA%\1C\1cv8\1cv8.pfl`, удаление блока `ModuleColorCategory` при закрытом конфигураторе, замер, возврат копии с проверкой хеша.

## Готовность

- (а) `timeline`: корзины с `new_ptr` / `new_hash` в D0–D3 — когда перестают появляться;
- (б) S10: `calls.new_ptr` ≈ 0;
- (в) T_settle для S2, S4, S6: от действия до последней корзины с `new_ptr` / `new_hash`.

Эталон готовности до 25 с при поздней загрузке не измерить: M3b даёт только состояние в ранний допустимый момент и T_settle.

## Что записать в `docs/measurements.md`, раздел «M3b»

- версия платформы, битность, `hooks` (state/patch), `getters_missing`, `features`;
- вердикт раскладки: `layout.decisive24` ≥ 1000, доля `decisive24 / (decisive24 + decisive20)` ≥ 99 %, `self_check` = `passed`;
- цвета текста (`text_colors.rgba`) по модулю (`caller`) и сценарию; `color_inexact`;
- альфа < 1: `alpha_lt1` (rgba, caller, calls), `calls.rgba_alpha_zero`;
- хеш-кандидат «Сохранить»: hex, w×h, кратность `hits` в S7 против S8 (S9 — смена состояния);
- верхние бины `dup.bins` (dx, dy, признаки) для S2 и S3, `dup.dt_log2`;
- кадр S1: среднее `frame.sum_us / frame.count`, p50/p90 по `frame.hist` (бин 250 мкс), `overhead_ticks / orig_ticks`;
- готовность (а), (б), T_settle.

Только числа, hex и basename. Текст модулей, заголовки окон и снимки экрана в документацию не попадают.

## Если данных нет

- `text_colors` пуст при ненулевом `calls.glyph_calls` — смотреть `calls.source_nonsolid`, `calls.color_error`.
- `calls.glyph_calls` = 0 — текст, вероятно, идёт через `cairo_show_text_glyphs`: 4-й хук только по решению владельца.
- Нет корреляции «Сохранить» в S7–S9 (`hits` S7 ≈ S8) — стоп и решение владельца: значок может рисоваться не через `cairo_pattern_create_for_surface`.
- `overflow.*_full` > 0 — таблица мала; записать, данные остаются верными для попавших ключей. Исключение — `overflow.ptr_full` (счётчик накопительный): если он вырос между дампами, `new_ptr` в этой эпохе занижен, и выводы о готовности (а), (б), T_settle по ней недействительны.
